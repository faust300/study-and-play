# study-and-play

Claude가 낸 알고리즘 문제를 Go로 직접 풀며 코딩 감각을 되찾는 저장소다. 콜백 재시도, 정산, 점검 시간대처럼 실무에서 만난 상황을 소재로 삼고, 문제를 하나씩 풀면서 Go 문법과 표준 라이브러리에 익숙해지는 게 목표다.

## 진행 방식

1. **출제** — Claude가 문제 설명, `// TODO`가 있는 함수, 채점용 테스트를 준비한다. Claude의 정답 풀이는 테스트 검증에만 사용한다.
2. **풀이** — 빈 함수를 직접 구현하고 `go test`로 결과를 확인한다.
3. **힌트** — 막히면 Claude에게 어느 지점에서 풀이가 어긋났는지, 다음에 무엇을 살펴보면 좋을지 묻는다.

## 로드맵

한 묶음에 새 Go 문법은 1~2개만 넣고, 뒤로 갈수록 실제 백엔드 코드에 가까운 모양으로 넘어간다. 아래 순서는 진행하면서 조정할 수 있다.

| 단계 | 묶음 | 새로 배우는 Go | 주제 |
| --- | --- | --- | --- |
| 기초 | 001~003 | 변수, `for`, 맵, 슬라이스, 구조체, 정렬 | 콜백 재시도, 정산 순위, 점검 시간대 |
| | 004 | `error`, `strings`·`strconv`, 메서드 | 콜백 로그 파싱, 재시도 대기열 |
| 타입 설계 | 005 · 인터페이스 | `interface`, 타입 스위치, 임베딩 | 알림 발송기(푸시, 이메일)를 같은 인터페이스로 바꿔 끼우기 |
| | 006 · 제네릭 | `[T any]`, `comparable`, `container/list` | 004의 대기열을 `Queue[T]`로 일반화, `Set[T]`, LRU 캐시 |
| 시간과 흐름 | 007 · 시간과 컨텍스트 | `time.Time`·`Duration`, `context.WithTimeout` | 지수 백오프 일정, lease 만료 판정, 72시간 결과 규칙 |
| 동시성 | 008 · 고루틴과 채널 | `go`, `chan`, `select`, `sync.WaitGroup` | 워커 풀로 영상 작업 나눠 처리, 결과 순서 맞추기 |

## 문제 묶음 구성

004부터 한 묶음은 세 문제로 나눈다.

1. **몸풀기** — 새 문법만 써 보는 짧은 문제. 조건은 1~2개로 제한한다.
2. **핵심** — 새 문법으로 실무 상황 하나를 푼다.
3. **응용** — 이전 묶음의 풀이와 합친다. 004의 `Summarize`가 001 풀이를 다시 쓰는 식이다.

각 파일 맨 위 주석에 난이도(★~★★★)와 그 문제에서 처음 나오는 문법을 적는다.

## 테스트 실행

Go 1.23 이상에서 저장소 루트를 기준으로 실행한다.

| 용도 | 명령어 |
| --- | --- |
| 전체 문제 채점 | `go test ./...` |
| 002번 묶음의 테스트 결과 자세히 보기 | `go test -v ./002-map-slice-drills` |
| Two Sum만 채점 | `go test -v -run '^TestTwoSum$' ./002-map-slice-drills` |
| 콜백 로그 100만 건 벤치마크 | `go test -bench=. ./001-callback-retry` |
